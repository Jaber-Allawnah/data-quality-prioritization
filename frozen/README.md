# `frozen/`

Outputs frozen at the close of the study (10 August 2026), kept separate
from `results/` because they document *how* the results were verified, not
just what they are. Cross-reference: `docs/RESEARCH_LOG.md`, "Final entry —
10 August 2026" for the full narrative behind the files below.

| File | What it is |
|---|---|
| `CHECKSUMS.txt` | Manifest generated by `make_manifest.py`. This is the mechanism that caught the cost-data contamination incident described below — it detected `results/cleaning_costs.csv` changing after the freeze, rather than the change passing silently. |
| `analysis_output.txt` | Full authoritative output of `analyse_results.py` — the damage table, mechanism comparisons, RQ3/RQ4 figures. |
| `rq2_model_output.txt` | Full authoritative output of `build_roi_model.py` — cost bands, `E_benchmark`, break-even thresholds. This is **run 4**, the same run backing `results/cleaning_costs.csv`. |
| `audit_cost_stability_output.txt` | The two-run stability comparison cited in the paper's "Cost Bands, Not Fine Ordering" section (every cell timed twice, band assignment checked for reproducibility). |
| `cleaning_costs_PREVIOUS_RUN.csv` | The **previous** half of that same two-run comparison — paired with the **current** `results/cleaning_costs.csv`. Not authoritative on its own; kept only because it's the other side of a specific check the paper reports numbers from (e.g. the "87.8 to 67.9 seconds" example). |
| `make_manifest.py` | Generates `CHECKSUMS.txt`. |
| `timing_runs/` | Raw evidence for two of the three independent timing runs the paper reports for `E_benchmark` reliability — see below. |

## `timing_runs/`

The paper reports three independent timing runs for the `IQR clipping` /
`E_benchmark` reliability check. Renamed from their original filenames for
clarity; content is otherwise untouched.

| File | Original filename | Run | IQR clipping cost | `E_benchmark` |
|---|---|---|---|---|
| `run1_roi_output.txt` | `roi.txt` | 1 | 0.0127s | 207.5 pp/s |
| `run2_cost_output.txt` | `cost_rerun.log` | 2 | 0.0123s | 215.0 pp/s |

Run 3 (0.0215s, contaminated by concurrent CPU load from an unrelated job)
and run 4 (0.0118s, 222.4 pp/s — **authoritative**, and the run behind
every headline cost figure in the paper) are **not** shipped as separate
raw files here:

- Run 3's numbers are preserved in `docs/RESEARCH_LOG.md` ("Final entry —
  10 August 2026") but the raw file is deliberately excluded — it is a
  known-bad measurement, and shipping it invites someone to mistake it for
  valid data.
- Run 4 is fully captured by `results/cleaning_costs.csv` and
  `rq2_model_output.txt` above, so no separate raw log is needed.

## What's excluded, and why

`cleaning_costs_CONTAMINATED_1848.csv` (run 3, above) and
`experiment_results_PRE_IQR_ARCHIVE.csv` (a pre-bugfix run, superseded after
the winsorisation fix described in `docs/RESEARCH_LOG.md`, "Bugs found and
fixed") are not included in this repository. Both are documented — what
they were and why they were rejected — in `docs/RESEARCH_LOG.md`. Shipping
the files themselves alongside the corrected data would create ambiguity
about which numbers are authoritative without adding anything a reader
couldn't already get from the log entry.
